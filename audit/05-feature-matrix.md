# Phase 5 — Feature Maturity Matrix

Cross-join of every Phase 1 reference item (237) against Phase 2 stated spec, Phase 3.B (DB), Phase 3.C (backend), Phase 3.D (frontend), and Phase 4 (tests). Maturity rubric:

- **0 Absent** — no mention, no code, no schema.
- **1 Acknowledged** — docs/backlog only.
- **2 Stubbed** — schema/scaffolding; no working business logic.
- **3 Partial** — happy-path BE _or_ FE; little/no test coverage; not E2E.
- **4 Functional** — E2E happy path (DB↔API↔UI) with at least three of: BE test, FE test/E2E, audit log, validation, RBAC.
- **5 Production-grade** — adds error handling, full audit trail, regulatory output verified.

Conservative defaults applied:

- Frontend is overwhelmingly stub-only (Phase 3.D F-1 to F-4): UI-dependent features capped at 3.
- Folha calculation tests assert only shape, not correctness (Phase 4 §6 critical findings 1–2): folha calculation features capped at 3.
- eSocial dispatcher is a sandbox echo with no XSD validation, no signing, no SOAP (Phase 3.C §9): eSocial event features capped at 2 unless a working business path exists.

Citations use `audit/0X-...md` section anchors when no `path:line` is available.
