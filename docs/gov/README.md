# Governance Artifacts (`docs/gov`)

This folder tracks governance controls and operational readiness for SGP v0.0.1.

## Key policies

- `docs/eng` is authoritative for engineering/product behavior.
- Code artifacts are authoritative in English.
- Runtime implementation must not add backward compatibility layers or legacy shim schemas.

## Files

- `generated/governance-manifest.json`: machine-readable governance inventory.
- `generated/runtime-topology.json`: machine-readable runtime topology consumed by health checks.
- `generated/api/route-alignment.json`: generated API route-contract surface.
- `generated/database/alignment-matrix.json`: generated database alignment matrix.
- `evidence/`: persistent implementation status, closure ledgers, and gate evidence.
- `evidence/repository-discipline.md`: retained repository discipline, ownership,
  branch protection, and gate evidence.
- `audit/type-safety-proof.md`: strict TypeScript and branded-ID proof.
- `audit/test-confidence-proof.md`: coverage, mutation, type, and mixed-test proof.
- `compliance/scoring.md`: current control scoring and known gaps.
- `health/preflight.md`: preflight checks before deploy or migration.
- `audit/README.md`: audit logging model and retention notes.
- `observability/`: governed Grafana dashboards and Prometheus alert rules.

## Validation

The active non-mutating governance gate is:

```bash
npm run governance:check
```

It validates runtime pins, single workspace lockfile layout, reverse-evidence succession coverage, `devai.config.json`, manifest evidence paths, canonical root scripts, live-doc backticked path references under `docs/eng`, `docs/gov`, and `docs/user`, ADR structure, architecture maps, type-safety gates, mutation gates, operator docs, API docs, and repository discipline evidence. Future devai-generated manifests should be regenerated by tooling and then validated here, not hand-maintained as product truth.
