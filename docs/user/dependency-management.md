# Dependency Management

Date: 2026-05-24

## Local STYNX Packages

SGP consumes shared STYNX packages from local tarballs generated by the sibling
checkout at `/Users/aarusso/Development/stech/stynx`.

The tarballs live under:

```text
/Users/aarusso/Development/stech/stynx/.release/local-npm/
```

SGP references those tarballs through `file:` dependencies in workspace package
manifests. They are intentionally local development artifacts and are not
committed into SGP.

## Refresh Procedure

1. In the `stynx` checkout, run the documented local package release command for
   the package being refreshed.
2. Confirm the expected tarball exists under `.release/local-npm/`.
3. In SGP, run `npm install` from the repository root.
4. Review `package-lock.json` integrity changes intentionally.
5. Run focused SGP gates for the touched package boundary, then broaden to the
   relevant root gate.

## Failure Modes

- Missing tarball: regenerate the package in the sibling `stynx` checkout.
- Integrity mismatch: rerun `npm install` after confirming the tarball was
  intentionally regenerated.
- Unexpected package API drift: update SGP code and tests against the accepted
  `docs/eng/` behavior; do not add compatibility shims for v0.0.1.
- CI without sibling tarballs: use a registry or artifact-publishing path
  approved for the target environment rather than committing local tarballs.
