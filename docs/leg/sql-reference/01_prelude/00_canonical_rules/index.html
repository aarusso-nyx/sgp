Canonical Migration Rules

Scope Freeze​

  • Inventory date: 2026-04-21.
  • Requested source database name: rhlinkcom.
  • Actual online source database inventoried: rhlinkcon.
  • Source engine observed: Microsoft Azure SQL Edge Developer 15.0.2000.1574, SQL Server-compatible catalog surface.
  • Canonical source schema partitioning strategy: schema-first. This inventory contains one user schema, dbo, so all generated PostgreSQL SQL will be partitioned under sql/10_core_ddl/dbo, sql/20_programmability/dbo, and sql/30_seed_data/dbo.
  • No worker may assume additional schemas, routines, triggers, sequences, filtered indexes, INCLUDE indexes, computed columns, rowversion columns, XML columns, JSON modules, or synonyms exist beyond what is present in sql/00_inventory.

Naming and DDL Conventions​

  • Preserve source snake_case names where possible.
  • Use lower-case, unquoted PostgreSQL identifiers unless quoting is strictly required.
  • Generate deterministic object names where SQL Server names are missing or non-portable:
    • primary keys: pk_<table>
    • foreign keys: fk_<table>__<referenced_table>__<ordinal>
    • unique constraints: uq_<table>__<columns>
    • checks: ck_<table>__<ordinal>
    • indexes: preserve source names if portable; otherwise ix_<table>__<columns>
  • All timestamps must be TIMESTAMP WITH TIME ZONE.
  • All character/string columns must be TEXT.
  • Encode build ordering numerically inside each subtree so orchestration is explicit.

Type Mapping Rules​

  • bigint -> BIGINT
  • int -> INTEGER
  • smallint -> SMALLINT
  • tinyint -> SMALLINT
  • bit -> BOOLEAN
  • decimal(p,s) / numeric(p,s) -> preserve precision and scale
  • money -> NUMERIC(19,4)
  • smallmoney -> NUMERIC(10,4)
  • float -> DOUBLE PRECISION
  • real -> REAL
  • uniqueidentifier -> UUID
  • date -> DATE
  • datetime, datetime2, smalldatetime, datetimeoffset -> TIMESTAMP WITH TIME ZONE
  • time -> TIME
  • char, nchar, varchar, nvarchar, text, ntext, sysname -> TEXT
  • binary, varbinary, image -> BYTEA
  • xml -> XML
  • rowversion / timestamp -> no direct timestamp mapping; emulate with a monotonic version column plus trigger if one is ever discovered after inventory

Identity and Sequence Rules​

  • SQL Server IDENTITY columns map to GENERATED BY DEFAULT AS IDENTITY.
  • Use BY DEFAULT rather than ALWAYS so explicit historical inserts remain possible during data loading.
  • Separate PostgreSQL sequences are created only when the source has standalone sequences or behavior that cannot be represented by identity columns.
  • Inventory found 126 identity columns and 0 standalone SQL Server sequences.

Constraint and Index Rules​

  • Primary keys, foreign keys, unique constraints, and checks must be emitted explicitly, never inferred.
  • Disabled or untrusted SQL Server constraints must be documented; PostgreSQL output should default to valid/enforced constraints unless a documented compatibility gap requires deferred validation.
  • SQL Server clustered/nonclustered indexes map to PostgreSQL indexes without promising physical row order. Any physical clustering expectation is a documented gap unless a later validation script proves the application depends on it.
  • Filtered indexes map to partial indexes.
  • SQL Server INCLUDE columns map to PostgreSQL INCLUDE (...).
  • SQL Server fill-factor settings are preserved when nonzero and supported.
  • Inventory found 0 filtered indexes and 0 INCLUDE indexes.

Computed, Temporal, and Versioning Rules​

  • Inventory found 0 computed columns. If a late-discovered computed column appears:
    • use GENERATED ALWAYS AS (...) STORED when PostgreSQL supports the expression
    • otherwise use a trigger-maintained physical column or a compatibility view, with the choice documented
  • Inventory found 0 rowversion/timestamp columns.
  • Inventory found 0 temporal/system-versioned tables.

Routine Translation Rules​

  • T-SQL routines translate to PostgreSQL plpgsql unless a SQL-language function is obviously sufficient.
  • GETDATE, SYSDATETIME, CURRENT_TIMESTAMP-style SQL Server calls map to PostgreSQL CURRENT_TIMESTAMP.
  • ISNULL maps to COALESCE.
  • TOP (n) maps to LIMIT n.
  • NEWID() maps to UUID generation via gen_random_uuid() unless a different extension is required by the final build script.
  • MERGE must be rewritten explicitly; no automatic translation is allowed.
  • Dynamic SQL must be minimized and documented when retained.
  • Inventory found 8 routines, all from the SQL Server sysdiagrams feature set:
    • fn_diagramobjects
    • sp_alterdiagram
    • sp_creatediagram
    • sp_dropdiagram
    • sp_helpdiagramdefinition
    • sp_helpdiagrams
    • sp_renamediagram
    • sp_upgraddiagrams
  • Canonical handling for sysdiagrams: treat SQL Server diagram support as a non-business legacy feature. Unless later code inspection proves application dependency, do not implement the SQL Server Management Studio diagram routine set in PostgreSQL; record it in the final gap report and preserve the backing table only if required for data fidelity.

Seed and Reference Data Rules​

  • Seed/reference data is determined by inventory evidence, not by name alone.
  • Current heuristic seed candidates are listed in sql/00_inventory/raw/seed_candidates.json.
  • Reference tables with low cardinality and high inbound foreign-key use must receive deterministic INSERT scripts.
  • Business tables containing transactional rows remain outside seed scripts unless explicitly required for a runnable baseline dataset.

Validation Rules​

  • Validation must prove object-category coverage against sql/00_inventory/raw/object_catalog.json.
  • Validation must include:
    • table/column/constraint/index coverage checks
    • foreign-key smoke checks
    • identity/default smoke checks
    • optional seed/reference row-count assertions
    • explicit gap verification for non-migrated sysdiagrams support objects

Worker Contract Freeze​

  • Workers may only write inside assigned subtrees.
  • Workers must use PostgreSQL-only syntax.
  • Workers must enumerate every in-scope source object from sql/00_inventory.
  • Any omission must be recorded as an unresolved item, never silently dropped.
